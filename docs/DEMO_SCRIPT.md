# Сценарий трёхминутного демо

## 0:00–0:25 — проблема

> Человек знает, что произошло в его жизни, но государственный каталог ожидает точное название услуги. Из-за незнакомых терминов пользователь тратит время и рискует подготовить неверные документы.

Показать пустой экран Qadam AI.

## 0:25–0:45 — ценность

> Qadam AI превращает описание жизненной ситуации в понятный проверяемый маршрут. Агент задаёт только необходимые вопросы, а факты берёт не из памяти модели, а из каталога с официальными источниками.

## 0:45–1:45 — живой сценарий

1. Ввести: «Я переехал в Астану и хочу зарегистрироваться по новому адресу».
2. Выбрать постоянную регистрацию.
3. Подтвердить согласие собственника.
4. Показать название услуги, документы, четыре шага и каналы получения.
5. Акцентировать ссылку eGov и дату проверки.

Не переключаться между окнами и не объяснять код во время основного сценария.

## 1:45–2:15 — безопасная работа AI

Ввести перефразированный запрос. Показать индикатор `OPENAI` или `LOCAL`.

> Модель отвечает только за понимание намерения и возвращает ID услуги через строгую JSON-схему. Она не может придумать новый документ или административное требование. Если API недоступен, приложение продолжает работать локально.

## 2:15–2:35 — честная граница

Ввести запрос про открытие ИП.

> Qadam AI распознаёт ситуацию, но не выдаёт маршрут, пока контент не проверен. Для государственного сервиса корректный отказ лучше уверенной выдумки.

## 2:35–3:00 — масштабирование

> Сегодня в каталоге пять ситуаций и один полностью проверенный маршрут. Следующий шаг — редакторский процесс обновления каталога, больше услуг и партнёрская интеграция с официальными источниками. Архитектура уже разделяет AI-классификацию и проверенные факты.

Завершить одной фразой:

> Qadam AI помогает сделать первый правильный шаг, когда человек ещё не знает официального названия услуги.

## Запасной план

- Держать локальный сервер и вкладку открытыми до презентации.
- Перед демо пройти сценарий один раз в режиме `LOCAL`.
- Если модель или интернет недоступны, не чинить API на сцене: показать fallback как свойство надёжности.
- Иметь скриншот готового результата, но сначала демонстрировать живой продукт.
