# Архитектура Qadam AI

## Решение для тренировочного MVP

Проект строится без внешних runtime-зависимостей:

- backend: Python 3.14 и `http.server`;
- frontend: HTML, CSS и vanilla JavaScript;
- данные: проверяемый JSON-каталог;
- AI: сменный адаптер с детерминированным fallback-режимом;
- тесты: стандартный модуль `unittest`.

Такой стек быстро запускается на новом компьютере, не зависит от установки пакетов и позволяет отдельно проверить продуктовый сценарий, даже если модель или сеть недоступны.

## Компоненты

```text
Browser
  |
  | POST /api/route
  v
HTTP API
  |
  +-- Intent matcher
  +-- Clarification policy
  +-- Verified service catalog
  +-- Response composer
  +-- Optional AI adapter
```

Каталог является источником фактов. Модель может классифицировать запрос, выбирать запись, формулировать объяснение и переводить текст, но не должна самостоятельно добавлять документы, сроки или требования.

## Агентный цикл

1. Нормализовать язык и текст запроса.
2. Сопоставить запрос с услугами каталога.
3. Если уверенность низкая или отсутствуют обязательные условия — вернуть один уточняющий вопрос.
4. После уточнения выбрать одну услугу.
5. Сформировать маршрут только из полей выбранной записи.
6. Добавить источник, дату проверки и предупреждение.

## Контракт API

### Запрос

`POST /api/route`

```json
{
  "message": "Я переехал в Астану и хочу зарегистрироваться по новому адресу",
  "locale": "ru",
  "answers": {}
}
```

### Уточнение

```json
{
  "status": "needs_clarification",
  "question": {
    "id": "has_owner_consent",
    "text": "У вас есть согласие собственника жилья?",
    "options": ["Да", "Нет", "Не знаю"]
  },
  "matchedServiceId": "residence-registration",
  "confidence": 0.78
}
```

### Готовый маршрут

```json
{
  "status": "ready",
  "service": {
    "id": "residence-registration",
    "title": "Регистрация по месту жительства",
    "reason": "Вы указали, что переехали и хотите зарегистрироваться по новому адресу."
  },
  "documents": [],
  "steps": [],
  "channels": [],
  "source": {
    "url": "",
    "verifiedAt": null
  },
  "notice": "Справочная информация. Перед подачей заявления проверьте требования на официальном ресурсе."
}
```

### Ошибка или неподдерживаемый запрос

```json
{
  "status": "unsupported",
  "message": "Пока я умею помогать только с пятью ситуациями из демонстрационного каталога.",
  "supportedServices": []
}
```

## Правила достоверности

- API не возвращает непроверенную запись как готовый маршрут.
- Пустой или просроченный источник переводит ответ в статус `content_unavailable`.
- Значимые факты копируются из каталога без генеративного дополнения.
- Для каждого ответа сохраняется идентификатор версии каталога, но не текст пользовательского запроса.

## План развития

AI-адаптер использует OpenAI Responses API со Structured Outputs. Он получает только пользовательский текст и список идентификаторов, названий и ключевых слов услуг и возвращает `service_id` с уверенностью. Фактический маршрут по-прежнему собирает backend из локального каталога.

Если `OPENAI_API_KEY` или `OPENAI_MODEL` не заданы либо API недоступен, приложение автоматически использует локальное сопоставление ключевых слов. Режим отображается в шапке интерфейса.
